# PLAN.md — «Можно ли на этом заработать?»

Инструкция для агента Claude, работающего в цикле, и для сайта, который показывает результат его работы. Документ самодостаточен: каждый раздел читается без обращения к другим разделам.

---

## Как ссылаться на график в markdown

Каждое утверждение о конкретном баре, сигнале, сделке или периоде в тексте агента сопровождается ссылкой на график. Сайт превращает ссылку в кнопку; по нажатию график показывает это место. Агент, который не смотрел на график, не может написать верную ссылку — это и есть проверка. Четыре формы:

```
[[t:2026-11-12T09:00Z]]                                        бар: время открытия бара, UTC, ISO 8601
[[t:2026-11-12T09:00Z@66561]]                                  бар и цена: график ставит перекрестие на этой цене
[[range:2026-11-19T00:00Z..2026-11-26T23:00Z]]                  период: от открытия первого бара до открытия последнего
[[trade:82]]                                                    сделка: id из trades в <id>_candles.json
[see the breakout](ref:range:2026-11-19T00:00Z..2026-11-26T23:00Z)   та же ссылка со своим текстом вместо автоматической подписи
```

Правила:

1. Время — всегда время **открытия** бара в UTC, формат ISO 8601 с `Z`. Минуты совпадают с сеткой таймфрейма: на 1h — `:00`, на 15m — `:00`, `:15`, `:30`, `:45`. Бар, которого нет в `bars` файла `<id>_candles.json`, график показать не может.
2. У периода начало раньше конца. Окно из C2 — это `[[range:…]]`, первая сделка окна — `[[trade:N]]`.
3. Id сделки — из `trades` в `<id>_candles.json` того же скрипта. Ссылка на сделку, которой там нет, — ошибка валидатора, и сервер с такой папкой не стартует. То же для периода, который кончается раньше начала, и для даты, которая не разбирается.
4. Ссылка пишется внутри предложения, подпись к ней сайт делает сам (дата бара, `#82 long +$172`). В форме `[текст](ref:…)` подписью становится текст агента. Ссылки допустимы и в ячейках таблицы.
5. Ссылки на одну и ту же сделку или бар можно повторять в разных сообщениях: счётчик «N on chart» считается по каждому сообщению отдельно, сообщение без ссылок сайт помечает «no chart references».

Где ссылки обязательны: A2 — сигнальный бар и сделка из него; A3 — проверенный бар; B1 (стратегия) — самая крупная сделка; C1 — самая прибыльная и самая убыточная сделки; C2 — окно и первая сделка окна; C5 — сделки худшего месяца; D3 — худший период; E1 — период новых баров и каждая сделка.

Так пишется хорошее предложение:

```
The fast SMA crossed above the slow one at [[t:2026-11-12T09:00Z@66561]]; the rule opened [[trade:82]] on the next open and closed it two days later at +$172.
```

Так — плохое, без ссылки его нельзя проверить:

```
The fast SMA crossed above the slow one on November 12 and the trade made money.
```

## 1. Задача

Агент берёт один Pine-скрипт с TradingView (индикатор или стратегию) и отвечает на единственный вопрос: **можно ли на этом скрипте заработать деньги, торгуя по алертам**. Все остальные свойства скрипта (перерисовка, частота сигналов, издержки) рассматриваются только как шаги к ответу на этот вопрос.

Агент работает в цикле. Первая итерация — полный разбор скрипта и бэктест. Каждая следующая итерация — досчёт новых баров, запись сделок в бумажный журнал и проверка, держится ли вердикт.

Сайт показывает результат: график TradingView-типа с индикатором и отметками сделок, вердикт, одну линию equity, код скрипта и текст агента в markdown. Каждая ссылка в тексте агента на бар, период или сделку — кнопка, по которой график показывает это место. Так читатель видит, смотрел ли агент на график.

Сайт статический и читает всё простыми GET-запросами из папки `data/` (раздел 5). Агент пишет файлы, локальный сервер `npx pine2profit <dir>` показывает их сразу, те же файлы без изменений публикуются на GitHub Pages. Пакет `pine2profit` на npm — это сайт, локальный сервер и валидатор папки `data/`.

Все деньги считаются в долларах на условный счёт **$10 000**, фиксированный номинал $10 000 на сделку, без плеча и без реинвестирования. Так каждый ответ читается как сумма, а не как процент.

## 2. Правила для агента

1. Числа в тексте берутся только из прогонов кода (pine2pyne → Python). Каждое число сопровождается id прогона. Число, которого нет в прогоне, не пишется.
2. Описание автора скрипта не является источником фактов. Факты — из кода и из прогонов.
3. Каждый ответ на вопрос — одно сообщение в `messages` файла `<id>_messages.json` (раздел 5): `code` — код вопроса (`A0`, `C7`, `E1`), `title` — название вопроса по-английски, `md` — 2–6 предложений, затем таблица `| metric | value |`. Заголовок внутри `md` не пишется, его даёт `title`. Графики агент не делает.
4. Запрещённые слова: «guaranteed», «proven», «holy grail», «works», «doesn't work» (без цифры), «scam». Любое утверждение о деньгах содержит сумму в $ и период.
5. Если скрипт закрытый (protected / invite-only) — агент останавливается после вопроса A1 с ответом «source not available, cannot evaluate».
6. Если скрипт не конвертируется в Python — агент пишет, какие конструкции не поддержаны, и останавливается с вердиктом UNKNOWN.
7. Агент не подбирает параметры. Параметры по умолчанию из скрипта — основные. Сдвиги параметров используются только для проверки устойчивости.
8. Каждое утверждение о конкретном баре, сигнале, сделке или периоде сопровождается ссылкой на график (синтаксис и правила — в разделе «Как ссылаться на график в markdown» в начале документа). Блок без единой ссылки на график сайт помечает как «no chart references».
9. Язык ответов — английский. Сайт англоязычный; заголовки блоков, таблицы и текст агента пишутся по-английски. Этот план — рабочий документ и остаётся на русском.
10. Каждому скрипту агент присваивает `kind` и `subcategory` (вопрос A1) и записывает их в строку индекса. Без категории скрипт не попадает в фильтры списка.
11. После каждой записи в `data/` агент запускает `npx pine2profit <dir> --check`. Пока команда возвращает ошибки, итерация не закончена: сервер с такой папкой не стартует, а сайт показал бы неверное или ничего.

## 3. Вопросы агенту для ИНДИКАТОРА

Каждый вопрос → одно сообщение `{ "code", "title", "md" }` в `<id>_messages.json`: `code` — код вопроса, `title` — заголовок по-английски, `md` — 2–6 предложений, затем таблица `| metric | value |`. Без графиков. Формулировки вопросов ниже даны по-русски для понимания.

### Блок A — что это и есть ли что торговать

**A0. Как это запускать: таймфрейм, время удержания, частота сигналов.**
Три ответа, каждый с цифрой:
1. *На каком таймфрейме запускать* (1m, 5m, 15m, 1h, 4h, 1D)? Основной — таймфрейм из публикации автора; если автор не указал или на нём меньше 30 сделок за 12 месяцев — ближайший более мелкий, где сделок ≥ 30. Для справки правило B1 прогоняется на авторском рынке на 15m, 1h, 4h и 1D за 12 месяцев: net $, сделок в месяц, медианное удержание. Таблица — для информации; «лучший по net» таймфрейм не выбирается, это подгонка.
2. *Через какое время после входа ожидать сигнал выхода?* Медиана и 80-й перцентиль длительности сделки от входа до выхода — в барах и в часах/днях; доля сделок, закрытых в течение суток и в течение недели. Одной фразой: «hold is hours / days / weeks».
3. *Сколько сигналов в месяц ожидать?* Среднее за 12 месяцев, самый тихий и самый активный месяц.
Таблица: таймфрейм → net $ 12 мес → сделок/мес → медианное удержание; отдельной строкой — рекомендованный таймфрейм, ожидаемое удержание, ожидаемое число сигналов в месяц. Все остальные ответы (A1–E3) даются на рекомендованном таймфрейме.

**A1. Что скрипт считает и какие сигналы выдаёт?**
Из кода перечислить все выходы: `alertcondition`, стрелки и метки (`plotshape`, `plotchar`, `label`), смена цвета линии или фона, пересечения линий скрипта между собой, горизонтальные уровни. Для каждого выхода указать, на какой строке он создаётся. Отметить, какие из них автор подразумевает как «вход» и «выход».
Таблица: выход → строка кода → тип (событие / линия / уровень / цвет) → роль по замыслу автора.

**Категория.** В этом же ответе агент присваивает скрипту `kind` и `subcategory` и записывает их в строку индекса (раздел 5). `kind` = `indicator`, если скрипт объявлен через `indicator()`. `subcategory` выбирается по тому, что скрипт считает и рисует, один ключ из списка:

| ключ | что это |
|---|---|
| `trend` | скользящие средние, ленты, облака, направление движения |
| `oscillator` | RSI, стохастик, MACD и другие осцилляторы в собственной шкале |
| `volatility` | ATR, Боллинджер, каналы, меры ширины движения |
| `volume` | объём, дельта, профиль, OBV, давление покупок и продаж |
| `structure` | уровни, зоны, пивоты, структура рынка |
| `signals` | готовые стрелки buy/sell, собранные из нескольких условий |

Если ни один ключ не подходит — новый ключ в нижнем регистре `[a-z0-9-]+` и одна фраза в тексте A1, почему; сайт показывает неизвестный ключ как есть и строит по нему фильтр. Последняя строка таблицы A1: `| category | indicator · <subcategory> |`.

**A2. Какой сигнал известен на закрытии бара и может быть поставлен в алерт?**
Для каждого выхода из A1 ответить: определяется ли он окончательно на закрытии бара, и можно ли на него поставить алерт TradingView с частотой «Once Per Bar Close». Если ни один выход напрямую не годится — переформулировать сигнал так, чтобы он определялся на закрытии (пример: «линия сменила цвет на закрытом баре», «закрытие пересекло уровень»). Результат — **торгуемый сигнал**, записанный словами и как условие на Pine. Если переформулировать невозможно — в строке индекса ставится `"usable": false`, блоки B и C не пишутся, агент пишет D1, D4, D5 и E; вердикт **NO**, сайт показывает «not tradeable» без правила и без денег. Иначе привести пример сигнального бара со ссылкой на график и сделку, которая из него получилась.
Таблица: торгуемый сигнал → условие Pine → как ставить алерт.

**A3. Перерисовывается ли торгуемый сигнал?**
Проверка: скрипт запускается на истории, обрезанной до бара t, и его выходы на барах ≤ t сравниваются с выходами полного прогона. Так на 200 точках t по всей истории. Ответ: меняется ли сигнал задним числом; если да — через сколько баров он становится окончательным. Эта задержка добавляется ко входу во всех расчётах блока C. Отдельно: есть ли в коде `request.security` с lookahead, `calc_on_every_tick`, `varip`, отрицательный offset в `plot`, пивоты с правым плечом — и что из этого влияет на торгуемый сигнал. Привести хотя бы один проверенный бар со ссылкой на график.
Таблица: сигналов изменено задним числом (%) → задержка до окончательного значения (баров) → находки в коде (строка → что).

**A4. Как часто срабатывает торгуемый сигнал?**
Сигналов в месяц на рынке и таймфрейме, которые автор указал в публикации (если не указал — BTCUSDT 1h). Сколько сигналов за всю историю и за последние 12 месяцев. Если за 12 месяцев меньше 30 сигналов — отметить, что данных для вердикта мало.
Таблица: рынок/ТФ → сигналов в месяц → за 12 мес → за всю историю.

### Блок B — превращение сигнала в сделку

**B1. Какое правило сделки из этого сигнала самое простое и честное?**
Агент выбирает одно основное правило и не более одного альтернативного. Вход — по алерту торгуемого сигнала, исполнение **по open следующего бара** (плюс задержка из A3, если есть). Выход — один из трёх вариантов: (а) по противоположному сигналу, (б) через N баров (N = медианное расстояние между сигналами), (в) стоп и тейк в единицах ATR(14). Правило записывается словами и как Pine-стратегия (поле `rule` в `<id>_pinescript.json`), которую любой читатель может поставить в алерт; отметки этой стратегии на графике — это и есть сделки, о которых идёт речь дальше.
Таблица: правило → вход → выход → направление (лонг / шорт / оба).

**B2. Какие издержки учтены?**
Комиссия, половина спреда, проскальзывание — по классу инструмента (крипто-перпы, FX, акции/индексы) из фиксированной таблицы издержек; задержка исполнения 1 бар. Если автор задал нулевые издержки — они заменены.
Таблица: класс → комиссия → спред/2 → проскальзывание → итого на сделку в $ при номинале $10 000.

**B3. Какой размер позиции?**
Фиксированный номинал $10 000 на сделку, без плеча и реинвестирования. Если правило B1 содержит стоп — дополнительно считать вариант с риском 1% ($100) на сделку, где размер позиции выводится из расстояния до стопа.
Таблица: вариант → размер → макс. одновременных позиций.

### Блок C — деньги

**C1. Сколько правило заработало или потеряло на авторском рынке и ТФ за всю историю?**
Net в $, число сделок, средняя сделка в $, доля прибыльных, максимальная просадка в $. Самая прибыльная и самая убыточная сделки — со ссылками на график.

**C2. То же за последние 12 месяцев.**
Отдельно, потому что это данные, на которых правило не подбиралось. Окно — со ссылкой на график как период; первая сделка окна — со ссылкой.

**C3. То же на 10 других рынках того же класса за последние 12 месяцев.**
Список рынков фиксирован для класса (для крипто: ETHUSDT, SOLUSDT, BNBUSDT, XRPUSDT, ADAUSDT, DOGEUSDT, AVAXUSDT, LINKUSDT, LTCUSDT, DOTUSDT; для FX и акций — свои фиксированные списки). Сколько рынков из 10 в плюсе после издержек.
Таблица: рынок → net $ за 12 мес → сделок.

**C4. Это лучше случайности?**
1000 прогонов, в каждом входы случайны с той же частотой, что у сигнала, выход — тот же, что в правиле B1. В каком перцентиле этого распределения результат правила за 12 месяцев на авторском рынке. Для сравнения — buy & hold на $10 000 за тот же период.
Таблица: правило $ → медиана случайных $ → перцентиль правила → buy & hold $.

**C5. Как это переживается?**
За 12 месяцев: сколько месяцев убыточны, худший месяц в $ (сделки худшего месяца — со ссылками на график), самая длинная серия убыточных сделок, самая долгая просадка в днях.

**C6. Что ломает результат?**
Net $ за 12 месяцев на авторском рынке: при удвоении издержек; при сдвиге каждого параметра индикатора на −30% и +30%; при задержке исполнения 2 бара вместо 1. Отметить, какой из вариантов переворачивает знак.
Таблица: вариант → net $ → знак сохранён (да/нет).

**C7. Главное число.**
Если бы последние 12 месяцев ставить алерты по правилу B1 и исполнять их по open следующего бара с издержками B2 на счёт $10 000 — сколько денег на счёте сейчас. Одно число в $ и одно предложение.

### Блок D — вердикт

**D1. Можно ли на этом заработать?**
Одно слово — **YES**, **NO** или **UNKNOWN** — и одна фраза почему.
Правило: **YES** — если C2 > 0, в C3 не меньше 6 рынков из 10 в плюсе, в C4 перцентиль ≥ 95, C7 > 0 и ни один вариант C6 не переворачивает знак. **UNKNOWN** — если за 12 месяцев меньше 30 сделок. Иначе **NO**.

**D2. Сколько.**
Ожидаемый результат в месяц на $10 000 — диапазон от худшего к лучшему, выведенный из C2, C3 и C5. Оценка агента, насколько вероятно, что преимущество настоящее, с опорой на перцентиль из C4.

**D3. При каких условиях это перестанет работать?**
Рынок, таймфрейм, рост издержек, режим рынка (тренд / флэт / высокая волатильность) — что из этого убивает результат, по данным C3 и C6. Худший период — со ссылкой на график.

**D4. Поставил бы агент на это свои $10 000 на 6 месяцев?**
Да или нет, одним абзацем, с причиной.

**D5. Что должно произойти в форвард-тесте, чтобы вердикт изменился?**
Конкретные условия с суммами и сроками. Примеры формулировок: «if the paper result over 3 months is below −$400 — the verdict changes to NO»; «if 4 of 6 months are positive and the total is above +$300 — the verdict changes to YES».

### Блок E — каждая итерация цикла

**E1. Что произошло с прошлой итерации?**
Сколько новых баров пришло (период — со ссылкой на график); какие алерты торгуемого сигнала сработали бы; какие сделки по правилу B1 открылись или закрылись в бумажном журнале — с временем, ценами, результатом в $ и ссылкой на каждую сделку.
Таблица: сделка → открыта → закрыта → направление → вход → выход → $.

**E2. Бумажный результат с первой итерации на $10 000.**
Сумма в $, число сделок. Совпадает ли с главным числом C7 по знаку и порядку величины; если нет — почему (режим рынка, издержки, редкость сигналов).

**E3. Изменился ли вердикт?**
Проверить условия из D5. Если вердикт изменился — написать, какое условие сработало. Если нет — написать, сколько ещё до ближайшего условия.

## 4. Вопросы агенту для СТРАТЕГИИ

Каждый вопрос → одно сообщение `{ "code", "title", "md" }` в `<id>_messages.json`: `code` — код вопроса, `title` — заголовок по-английски, `md` — 2–6 предложений, затем таблица `| metric | value |`. Без графиков.

### Блок A — что это и есть ли что торговать

**A0. Как это запускать: таймфрейм, время удержания, частота сделок.**
Три ответа, каждый с цифрой:
1. *На каком таймфрейме запускать* (1m, 5m, 15m, 1h, 4h, 1D)? Основной — таймфрейм из публикации автора; если автор не указал или на нём меньше 30 сделок за 12 месяцев — ближайший более мелкий, где сделок ≥ 30. Для справки стратегия прогоняется на авторском рынке на 15m, 1h, 4h и 1D за 12 месяцев при исполнении через алерты: net $, сделок в месяц, медианное удержание. Таблица — для информации; «лучший по net» таймфрейм не выбирается, это подгонка.
2. *Через какое время после входа ожидать сигнал выхода?* Медиана и 80-й перцентиль длительности сделки от входа до выхода — в барах и в часах/днях; доля сделок, закрытых в течение суток и в течение недели. Одной фразой: «hold is hours / days / weeks».
3. *Сколько сделок в месяц ожидать от стратегии?* Среднее за 12 месяцев, самый тихий и самый активный месяц.
Таблица: таймфрейм → net $ 12 мес → сделок/мес → медианное удержание; отдельной строкой — рекомендованный таймфрейм, ожидаемое удержание, ожидаемое число сделок в месяц. Все остальные ответы (A1–E3) даются на рекомендованном таймфрейме.

**A1. Что стратегия делает?**
Из кода: условия входа, условия выхода, направление (лонг / шорт / оба), стопы и тейки, фильтры. Для каждого — строка кода. Настройки `strategy()`: начальный капитал, размер позиции, комиссия, проскальзывание, `process_orders_on_close`, `calc_on_every_tick`, `calc_on_order_fills`, пирамидинг, bar magnifier.
Таблица: элемент → строка кода → что делает.

**Категория.** В этом же ответе агент присваивает скрипту `kind` и `subcategory` и записывает их в строку индекса (раздел 5). `kind` = `strategy`, если скрипт объявлен через `strategy()`. `subcategory` выбирается по логике входа и выхода, один ключ из списка:

| ключ | что это |
|---|---|
| `trend-following` | вход по направлению движения, выход при его смене |
| `mean-reversion` | вход против отклонения, выход на возврате к среднему |
| `breakout` | вход на пробое уровня, диапазона или канала |
| `grid-dca` | сетка ордеров, усреднение, DCA |
| `pattern-event` | свечные паттерны, время суток, календарные события |
| `composite` | несколько независимых систем или режимов в одном коде |

Если ни один ключ не подходит — новый ключ в нижнем регистре `[a-z0-9-]+` и одна фраза в тексте A1, почему; сайт показывает неизвестный ключ как есть и строит по нему фильтр. Последняя строка таблицы A1: `| category | strategy · <subcategory> |`.

**A2. Можно ли исполнять сигналы стратегии через алерты?**
Входы и выходы должны определяться на закрытии бара и исполняться по open следующего бара. Если стратегия исполняет ордера по закрытию того же бара (`process_orders_on_close=true`) или внутри бара (`calc_on_every_tick=true`) — записать, что через алерты так исполнить нельзя, и что все расчёты ниже сделаны с исполнением по open следующего бара. Если в стратегии стоп и тейк могут сработать в одном баре — записать, что принят худший порядок (сначала стоп). Привести пример сигнального бара и его сделки со ссылками на график.
Таблица: ордер → как у автора → как через алерты.

**A3. Перерисовывается ли список сделок?**
Проверка: стратегия запускается на истории, обрезанной до бара t, и её сделки на барах ≤ t сравниваются со сделками полного прогона. Так на 200 точках t. Ответ: доля сделок, которые меняются задним числом. Отдельно: `request.security` с lookahead, `varip`, пивоты, `timenow` — что из этого влияет на входы.
Таблица: сделок изменено задним числом (%) → находки в коде (строка → что).

**A4. Как часто стратегия торгует?**
Сделок в месяц на рынке и таймфрейме автора (если не указан — BTCUSDT 1h). Сколько сделок за всю историю и за последние 12 месяцев. Если за 12 месяцев меньше 30 сделок — отметить, что данных для вердикта мало.
Таблица: рынок/ТФ → сделок в месяц → за 12 мес → за всю историю.

### Блок B — что показывает тестер и что получится на самом деле

**B1. Какое число показывает тестер TradingView и почему оно такое?**
Воспроизвести результат тестера с настройками автора (его капитал, его размер позиции, его издержки, его режим исполнения). Записать net, просадку, число сделок. Затем перечислить, что в настройках автора завышает результат: нулевая комиссия, 100% капитала на сделку, исполнение по закрытию бара, отсутствие проскальзывания. Самую крупную сделку — со ссылкой на график.
Таблица: показатель → у автора → причина искажения.

**B2. Что получится при исполнении через алерты?**
Пересчёт на счёт $10 000: фиксированный номинал $10 000 на сделку, без реинвестирования; вход и выход по open следующего бара; издержки по классу инструмента (комиссия, половина спреда, проскальзывание); при стопе и тейке в одном баре — сначала стоп. Разница с B1 — разложить по причинам в $.
Таблица: причина → вклад в $.

**B3. Какая часть стратегии приносит деньги?**
Отключать по одному: правило входа (заменить на случайный вход той же частоты), правило выхода (заменить на выход через N баров), каждый фильтр. Net $ за 12 месяцев без каждого элемента.
Таблица: отключено → net $ → изменение $.

### Блок C — деньги

**C1. Сколько стратегия заработала или потеряла на авторском рынке и ТФ за всю историю** при исполнении через алерты (условия B2)?
Net в $, число сделок, средняя сделка в $, доля прибыльных, максимальная просадка в $. Самая прибыльная и самая убыточная сделки — со ссылками на график.

**C2. То же за последние 12 месяцев.**
Отдельно, потому что это данные, на которых стратегия не подбиралась. Окно — со ссылкой на график как период; первая сделка окна — со ссылкой.

**C3. То же на 10 других рынках того же класса за последние 12 месяцев.**
Список рынков фиксирован для класса (для крипто: ETHUSDT, SOLUSDT, BNBUSDT, XRPUSDT, ADAUSDT, DOGEUSDT, AVAXUSDT, LINKUSDT, LTCUSDT, DOTUSDT; для FX и акций — свои фиксированные списки). Сколько рынков из 10 в плюсе после издержек.
Таблица: рынок → net $ за 12 мес → сделок.

**C4. Это лучше случайности?**
1000 прогонов, в каждом входы случайны с той же частотой, что у стратегии, выход — тот же, что у стратегии. В каком перцентиле этого распределения результат стратегии за 12 месяцев на авторском рынке. Для сравнения — buy & hold на $10 000 за тот же период.
Таблица: стратегия $ → медиана случайных $ → перцентиль → buy & hold $.

**C5. Как это переживается?**
За 12 месяцев: сколько месяцев убыточны, худший месяц в $ (сделки худшего месяца — со ссылками на график), самая длинная серия убыточных сделок, самая долгая просадка в днях.

**C6. Что ломает результат?**
Net $ за 12 месяцев на авторском рынке: при удвоении издержек; при сдвиге каждого входного параметра стратегии на −30% и +30%; при задержке исполнения 2 бара вместо 1. Отметить, какой из вариантов переворачивает знак.
Таблица: вариант → net $ → знак сохранён (да/нет).

**C7. Главное число.**
Если бы последние 12 месяцев ставить алерты стратегии и исполнять их по open следующего бара с издержками на счёт $10 000 — сколько денег на счёте сейчас. Одно число в $ и одно предложение.

### Блок D — вердикт

**D1. Можно ли на этом заработать?**
Одно слово — **YES**, **NO** или **UNKNOWN** — и одна фраза почему.
Правило: **YES** — если C2 > 0, в C3 не меньше 6 рынков из 10 в плюсе, в C4 перцентиль ≥ 95, C7 > 0 и ни один вариант C6 не переворачивает знак. **UNKNOWN** — если за 12 месяцев меньше 30 сделок. Иначе **NO**.

**D2. Сколько.**
Ожидаемый результат в месяц на $10 000 — диапазон от худшего к лучшему, выведенный из C2, C3 и C5. Оценка агента, насколько вероятно, что преимущество настоящее, с опорой на перцентиль из C4.

**D3. При каких условиях это перестанет работать?**
Рынок, таймфрейм, рост издержек, режим рынка — что из этого убивает результат, по данным C3 и C6. Худший период — со ссылкой на график.

**D4. Поставил бы агент на это свои $10 000 на 6 месяцев?**
Да или нет, одним абзацем, с причиной.

**D5. Что должно произойти в форвард-тесте, чтобы вердикт изменился?**
Конкретные условия с суммами и сроками. Примеры: «if the paper result over 3 months is below −$400 — the verdict changes to NO»; «if 4 of 6 months are positive and the total is above +$300 — the verdict changes to YES».

### Блок E — каждая итерация цикла

**E1. Что произошло с прошлой итерации?**
Сколько новых баров пришло (период — со ссылкой на график); какие алерты стратегии сработали бы; какие сделки открылись или закрылись в бумажном журнале — с временем, ценами, результатом в $ и ссылкой на каждую сделку.
Таблица: сделка → открыта → закрыта → направление → вход → выход → $.

**E2. Бумажный результат с первой итерации на $10 000.**
Сумма в $, число сделок. Совпадает ли с главным числом C7 по знаку и порядку величины; если нет — почему.

**E3. Изменился ли вердикт?**
Проверить условия из D5. Если вердикт изменился — написать, какое условие сработало. Если нет — написать, сколько ещё до ближайшего условия.

## 5. Что агент записывает на диск

Все файлы лежат плоско в одной папке `<dir>/data/`, без подпапок. `<id>` — slug скрипта `[a-z0-9-]+`, он же префикс всех файлов этого скрипта. Доллары — целые числа на условный счёт $10 000. Поле, значение которого null, не пишется.

```
<dir>/data/
  index_1.jsonl                    список: одна строка JSON на скрипт, ~1000 строк в файле; index_2.jsonl, … продолжают его
  <id>_messages.json               текст агента: ответы на вопросы разделов 3–4
  <id>_candles.json                бары, сделки и equity для графика
  <id>_pinescript.json             исходник автора и торгуемое правило (необязательный файл)
```

### `index_N.jsonl` — строка индекса

Сайт читает `index_1`, затем `index_2`, … и останавливается на первом отсутствующем файле. **Поздняя строка с тем же `id` заменяет раннюю**, поэтому каждая итерация дописывает строку в конец последнего файла, старые файлы не переписываются. Когда в последнем файле около 1000 строк — начинается `index_{N+1}`.

Обязательные поля: `id`, `title`, `kind`, `verdict`, `updated`.

```json
{"id":"sma-cross-20-50","title":"SMA Cross 20/50","kind":"strategy","subcategory":"trend-following","verdict":"NO","main":-2465,"paper":461,"paperTrades":3,"expected":[-599,181],"iterations":3,"updated":"2026-11-26","market":"BTCUSDT","timeframe":"1h","license":"MPL-2.0","author":"example_author","tvUrl":"https://www.tradingview.com/script/EXAMPLE02/","cycleStart":"2026-11-12","percentile":59,"reason":"12 months −$2,465; only 4/10 markets positive; not better than random entries (59th percentile)"}
```

| поле | тип | откуда |
|---|---|---|
| `id` | string | slug скрипта |
| `title` | string | название у автора |
| `kind` | `indicator` \| `strategy` | A1: `indicator()` или `strategy()` |
| `subcategory` | string | A1: ключ из таблицы категорий или новый ключ `[a-z0-9-]+` |
| `usable` | boolean | A2 индикатора: `false`, если ни один сигнал не определяется на закрытии бара |
| `verdict` | `YES` \| `NO` \| `UNKNOWN` | D1 |
| `main` | number | C7: результат 12 месяцев через алерты, $ |
| `paper`, `paperTrades` | number | E2: бумажный результат с начала цикла, $ и число сделок |
| `expected` | `[low, high]` | D2: ожидаемый результат в месяц на $10 000 |
| `iterations` | number | номер последней итерации |
| `updated` | `YYYY-MM-DD` | дата последней итерации |
| `market`, `timeframe` | string | рынок и таймфрейм из A0 |
| `license`, `author`, `tvUrl` | string | из публикации на TradingView |
| `cycleStart` | `YYYY-MM-DD` | дата первой итерации; линия на графике и на equity |
| `percentile` | number | C4: перцентиль правила против случайных входов |
| `reason` | string | одна фраза из D1 |

Строка индикатора, который не торгуется:

```json
{"id":"volume-pressure","title":"Volume Pressure Delta","kind":"indicator","subcategory":"volume","usable":false,"verdict":"NO","iterations":1,"updated":"2026-11-26","market":"BTCUSDT","timeframe":"1h","license":"MPL-2.0","author":"example_author","tvUrl":"https://www.tradingview.com/script/EXAMPLE03/","cycleStart":"2026-11-26","reason":"not tradeable: the signal depends on realtime tick data (varip) and cannot be reproduced on history, so no rule can be executed through alerts"}
```

### `<id>_messages.json` — текст агента

```json
{
  "head": {"id":"sma-cross-20-50","title":"SMA Cross 20/50","kind":"strategy","subcategory":"trend-following","verdict":"NO","main":-2465,"paper":461,"paperTrades":3,"expected":[-599,181],"iterations":3,"updated":"2026-11-26","market":"BTCUSDT","timeframe":"1h","license":"MPL-2.0","author":"example_author","tvUrl":"https://www.tradingview.com/script/EXAMPLE02/","cycleStart":"2026-11-12","percentile":59,"reason":"12 months −$2,465; only 4/10 markets positive; not better than random entries (59th percentile)"},
  "groups": [
    { "code": "A", "title": "What it is" },
    { "code": "B", "title": "Tester vs. alerts" },
    { "code": "C", "title": "Money" },
    { "code": "D", "title": "Verdict" },
    { "code": "E", "title": "Iterations" }
  ],
  "messages": [
    { "code": "A0", "title": "How to run it: timeframe, holding time, signal frequency", "md": "The author publishes on BTCUSDT 1h; 97 trades in the last 12 months, so 1h is the timeframe for every answer below.     { "code": "E1", "title": "What happened since the previous iteration?", "md": "168 new bars [[range:2026-11-19T00:00Z..2026-11-26T00:00Z]]; one alert fired; trade [[trade:1]] closed at −$196.\n\n| metric | value |\n|---|---|\n| new bars | 168 |\n| trades closed | 1 |", "iteration": 3, "date": "2026-11-26" },
    { "code": "E2", "title": "Paper result since the first iteration on $10,000", "md": "+$461 over 3 trades since the cycle start; same sign as C7 is not confirmed yet.\n\n| metric | value |\n|---|---|\n| paper $ | +461 |\n| trades | 3 |", "iteration": 3, "date": "2026-11-26" },
    { "code": "E3", "title": "Did the verdict change?", "md": "No. D5 asks for a paper result below −$400 over 3 months; it is +$461.\n\n| metric | value |\n|---|---|\n| verdict | NO |\n| distance to the nearest D5 condition | $861 |", "iteration": 3, "date": "2026-11-26" },
    { "code": "E1", "title": "What happened since the previous iteration?", "md": "168 new bars [[range:2026-11-12T00:00Z..2026-11-19T00:00Z]]; no alert fired.\n\n| metric | value |\n|---|---|\n| new bars | 168 |\n| trades closed | 0 |", "iteration": 2, "date": "2026-11-19" }
  ]

```

- `head` — строка индекса этого скрипта, скопированная как есть. По ней страница рисует шапку при прямой ссылке. Валидатор требует точного совпадения со строкой индекса.
- `groups` — левая навигация страницы в этом порядке: для индикатора `A` What it is, `B` Signal → trade, `C` Money, `D` Verdict, `E` Iterations; для стратегии `B` называется Tester vs. alerts. Группа без сообщений не показывается, поэтому у неторгуемого индикатора `B` и `C` можно не объявлять.
- `messages` показываются в порядке файла, ничего не дедуплицируется: агент кладёт в файл то, что должна показать страница. Сообщение попадает в группу по буквенному префиксу `code` (`A0` → `A`), или по явному полю `group`.
- Сообщения без `iteration` идут под заголовком «Analysis»: это последние версии ответов A–D. Сообщения с `iteration` и `date` образуют секцию «Iteration NNN»: это блок E каждой итерации, последняя итерация первой.
- Файл переписывается целиком на каждой итерации: ответы A–D берутся из последней итерации, где они менялись, блоки E добавляются за новую итерацию.

**Ссылки на график** внутри `md` — четыре формы, правила их написания в разделе «Как ссылаться на график в markdown» в начале документа:

```
[[t:2026-11-12T09:00Z]]                            бар (время открытия, UTC)
[[t:2026-11-12T09:00Z@66561]]                      бар и цена на нём
[[range:2026-11-19T00:00Z..2026-11-26T23:00Z]]      период: обе границы отмечены
[[trade:82]]                                        сделка с id из <id>_candles.json
[see the breakout](ref:range:2026-11-19T00:00Z..2026-11-26T23:00Z)   то же, как обычная ссылка с текстом
```

Время — всегда время открытия бара в UTC в формате ISO. Id сделки — из `trades` в `<id>_candles.json` того же скрипта. Валидатор отвергает ссылку на сделку, которой нет, период, который кончается раньше начала, и дату, которая не разбирается. График строится по `bars` этого же файла, поэтому ссылки всегда попадают в те же свечи, которые видел агент.

```json
    { "id": 1, "iteration": 0, "side": "long", "open_time": 1732928400000, "open_price": 61642.5, "close_time": 1732996800000, "close_price": 60510.8, "pnl_usd": -195.58 }
  ],
  "equity": [
    { "time": 1732665600000, "backtest_usd": 0, "paper_usd": null },
    { "time": 1732996800000, "backtest_usd": -195.58, "paper_usd": null }
  ]
}
```

- `bars` — бары, на которых считал агент; `time` в миллисекундах UTC, строго по возрастанию, `high ≥ low`.
- `trades` — бэктест и бумажный журнал: `iteration` 0 для бэктеста, номер итерации для бумажных сделок; у открытой сделки `close_time` и `close_price` равны null; `id` уникальны.
- `equity` — одна линия: до начала цикла `paper_usd` = null, после начала `backtest_usd` = null. Без `equity` панели P&L на странице нет.

### `<id>_pinescript.json` — код

```json
{
  "source": "//@version=5\nindicator(\"EMA Ribbon\", overlay=true)\nplot(ta.ema(close, 20))\nplot(ta.ema(close, 50))",
  "rule": "//@version=5\nstrategy(\"EMA Ribbon rule\", overlay=true, initial_capital=10000)\nif ta.crossover(ta.ema(close, 20), ta.ema(close, 50))\n    strategy.entry(\"Long\", strategy.long)\nif ta.crossunder(ta.ema(close, 20), ta.ema(close, 50))\n    strategy.close(\"Long\")"
}
```

- `source` — исходник автора без изменений, заголовок лицензии сохраняется; показывается в редакторе и исполняется на графике как индикатор.
- `rule` — торгуемое правило как Pine-стратегия: для индикатора — правило из B1, для стратегии — её же код с исполнением по open следующего бара; исполняется на графике как стратегия, её отметки исполнений и есть сделки, о которых идёт речь в тексте. Для неторгуемого индикатора `rule` не пишется.
- Файл необязателен: без него страница показывает текст без панели кода.

### Проверка

`npx pine2profit <dir> --check` проверяет папку и возвращает 0 без ошибок или 1 с перечнем проблем: `data/index_1.jsonl:3` для строки индекса, `data/<id>_messages.json  messages[2].md` для места в документе. Проверяются существование `data/` и `index_1.jsonl`, нумерация индексов без пропусков, схема каждой строки (обязательные поля, типы, значения, запрет неизвестных полей с подсказкой правильного имени), наличие `_messages.json` и `_candles.json` у каждого скрипта из индекса, совпадение `head` со строкой индекса, схемы всех трёх файлов, ссылки на график. Та же проверка выполняется при каждом запуске `npx pine2profit <dir>`: с ошибками сервер не стартует. Предупреждения (файлы без строки индекса, посторонние файлы, отсутствующий `head`) не блокируют. Полный контракт с примерами печатает `npx pine2profit --help`.

## 6. Сайт

Статический сайт на английском: Next.js с экспортом в HTML, пакет `pine2profit` на npm, размещение на GitHub Pages. Сайт ничего не знает о скриптах заранее: все данные читаются в браузере простыми GET-запросами из `data/` по относительным путям, поэтому один и тот же экспорт работает и под `npx pine2profit <dir>`, и на Pages, куда `data/` кладётся рядом со сборкой. Шапка: название, ссылка на список, переключатель светлой/тёмной темы, ссылка на GitHub.

**Список скриптов** (`/`). Сетка карточек, подгружается по мере чтения `index_1.jsonl`, `index_2.jsonl`, …; виртуализирована, десятки тысяч карточек прокручиваются без пагинации. На карточке: `kind · subcategory` (и «not tradeable»), вердикт, название, 12 months via alerts, paper journal с числом сделок, expected per month, число итераций, дата. Фильтры: индикаторы / стратегии; вердикт; чипы подкатегорий, которые строятся из значений `subcategory` в данных, с количеством совпадений. Сортировка: вердикт, 12 months via alerts, paper journal, expected per month, updated, name; направление переключается. Состояние фильтров лежит в адресе (`?kind=indicator&verdict=YES&sub=trend&sort=updated&dir=asc`), ссылку можно отправить.

**Страница скрипта** (`/run/?id=<id>`; id в query, потому что при статическом экспорте страницы для неизвестных заранее id не существует):
1. **Шапка** из строки индекса: название, `kind`, подпись категории, рынок и таймфрейм, лицензия, ссылка на автора (`tvUrl`), дата.
2. **Вердикт** во всю ширину: слово из D1 (и «not tradeable» при `usable: false`), expected per month с перцентилем из C4, 12 months via alerts из C7 (сумма на счёте и результат), paper journal с числом сделок и датой начала цикла, число ссылок на график в тексте и число блоков без ссылок, фраза из `reason`.
3. **Три колонки.** Слева закреплённая навигация из `groups`: пункты — коды сообщений, для группы итераций — номера итераций; подсвечивается блок под верхом экрана. В центре: панель кода `source` в редакторе Ace с подсветкой Pine (только чтение, без CDN) — если есть `<id>_pinescript.json`; заголовок «Analysis» и сообщения без итерации; затем секции «Iteration NNN» с датой. Справа закреплённая панель графика (Vela + Vela-pinets: бары из `candles.bars`, `source` как индикатор, `rule` как стратегия с отметками исполнений; над шкалой времени — отметка на каждую ссылку агента; пунктир «cycle start»; ссылка на TradingView; логотип Vela отключён) и под ней линия P&L из `equity`, если точек больше одной.
4. Клик по ссылке в тексте: бар — перекрестие и цена или вертикальная линия; период — две границы; сделка — бокс от входа до выхода с суммой и стрелки. Над графиком показано, что сейчас в фокусе, и кнопка reset. У каждого блока — счётчик «N on chart» или пометка «no chart references».

Больше ничего на странице нет.

**Локальный просмотр и публикация.** `npx pine2profit <dir>` проверяет `<dir>/data` и поднимает сайт на `http://localhost:60050`; сервер отдаёт только статику сайта и `GET /data/<file>` без кэша, никакого API. Для GitHub Pages сборка делается с `NEXT_PUBLIC_BASE_PATH=/<repo>`, `data/` копируется в `out/data/`, публикуется `out/`; адреса те же: `https://<owner>.github.io/<repo>/` и `…/run/?id=<id>`.
